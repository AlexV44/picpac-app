# Интеграция с CRM PicPac: персональные предложения

Приложение берёт «портрет» вошедшего клиента из CRM по API и на его основе показывает персональные предложения
на главной («Для вас») и применяет скидку при оформлении заказа. Клиенты не из CRM (гости, новые) видят приложение как раньше.

## Подключение

| Переменная | Значение |
|---|---|
| `CRM_MODE` | `mock` (по умолчанию, демо-CRM внутри сервера), `http` (настоящая CRM), `off` (выключено) |
| `CRM_URL` | база API, например `https://crm.picpac.by/api/v1` (для `http`) |
| `CRM_TOKEN` | Bearer-токен сервисного доступа |
| `CRM_TIMEOUT` | таймаут запроса, секунд (по умолчанию 2,5) |
| `CRM_CACHE_SECONDS` | кэш портрета в памяти (по умолчанию 300) |

Пример `.env` для боевой CRM:
```
CRM_MODE=http
CRM_URL=https://crm.example/api/v1
CRM_TOKEN=...
```
Проверить подключение можно из админ-панели: вкладка «Сводка», блок «Интеграция с CRM» (режим, связь, запросы, обращения к кэшу).
Для демонстрации HTTP-режима без настоящей CRM: `CRM_MODE=http CRM_URL=http://localhost:8000/mock-crm/v1 CRM_TOKEN=demo-crm-token`.

## Что должна отдавать CRM (контракт)

```
GET {CRM_URL}/customers/lookup?email=<e-mail>     Authorization: Bearer <CRM_TOKEN>
GET {CRM_URL}/customers/<id>
200 -> JSON-портрет     404 -> клиента нет (это не ошибка)
```
Портрет (лишние поля приложение отбрасывает, белый список в `crm.py`):

| Поле | Тип | Смысл |
|---|---|---|
| `id`, `name` | строка | идентификатор и имя |
| `segment` | `new` / `regular` / `loyal` / `vip` / `sleeping` | сегмент |
| `since` | дата ISO | клиент с |
| `orders_count`, `total_spent`, `avg_check` | число | история заказов |
| `last_order_date`, `last_product` | дата, id продукта | последний заказ |
| `favorite_product`, `kinds` | id, `{book: n, print: n}` | предпочтения |
| `discount_percent`, `loyalty_level` | 0–30, строка | личная скидка и уровень |
| `birthday` | `MM-DD` | день рождения |
| `events` | `[{title, date}]` | события (например, день рождения ребёнка) |
| `summary`, `interests` | текст, список | краткое описание клиента |
| `marketing_consent` | bool | согласие на персональные предложения; `false`: предложений нет |

Сопоставление клиента: по e-mail аккаунта (для вошедшего клиента). Гости и администраторы в CRM не запрашиваются.
Пример ответа: `curl -H "Authorization: Bearer demo-crm-token" "localhost:8000/mock-crm/v1/customers/lookup?email=vip@picpac.test"`.

## Какие предложения и почему

Правила прозрачны, у каждого есть причина, показываемая клиенту («Почему вы это видите»), и срок.

| Предложение | Условие в портрете | Эффект |
|---|---|---|
| День рождения | ближайший день рождения в окне −3…+10 дней | −15% (VIP −20%) на любой заказ |
| К празднику | событие в ближайшие 30 дней | −10% и предложение собрать фотокнигу |
| «Мы скучаем» | последний заказ более 90 дней назад | −12% на следующий заказ |
| Личная скидка | `discount_percent` > 0 | −N% автоматически |
| Доставка для VIP | сегмент `vip` | бесплатная доставка |
| Кросс-продажа | только книги → печать, только печать → книга | предложение без скидки, открывает выбор услуги |
| Повтор | любимая фотокнига и недавний заказ | предложение начать новый проект |

**Правила скидок.** Проценты не суммируются: действует наибольший (персональный или по промокоду). Бесплатная доставка добавляется отдельно.
Процент всегда считает сервер по портрету из CRM, клиентское приложение присылает только «применять предложения / не применять»,
поэтому подменить размер скидки в запросе нельзя. В заказе сохраняется основание скидки (подпись в чеке).

## Надёжность и приватность

- CRM недоступна, медленная или ответила ошибкой: приложение работает без персонализации; после сбоя CRM 30 секунд не опрашивается, сбой виден админу.
- Портрет живёт в памяти сервера до 5 минут, на диск не записывается; сбрасывается при выходе и удалении данных.
- Берутся только поля из белого списка; в клиентское приложение уходят предложения и имя, финансовые поля (суммы, средний чек) не передаются.
- Клиент может выключить персональные предложения в настройках («Персональные предложения») или кнопкой «Не применять» при оформлении.
- Без `marketing_consent=true` предложений нет.

## Демо-клиенты (синтетические)

| Вход | Что увидите |
|---|---|
| `client@picpac.test` / `client123` | скидка −5%, «К празднику» (день рождения сына через 19 дней) −10%, повтор Premium |
| `vip@picpac.test` / `vip123` | день рождения −20%, личная −10%, бесплатная доставка |
| `sleep@picpac.test` / `sleep123` | «Мы скучаем» −12%, предложение собрать фотокнигу |

Даты в демо считаются от текущего дня, поэтому предложения срабатывают в любой день. 240 синтетических портретов лежат в `seed/crm_portraits.json`
(`python seed_data.py`) и доступны через `/mock-crm/v1/customers/<id>`.

## Как расширять

Правила лежат в `offers.py` (функция `build`): новое предложение это один вызов `add(...)` с условием по портрету. Подмена источника данных
делается в `crm.py` (функция `_fetch`): если поля настоящей CRM называются иначе, достаточно сопоставить их в `normalize`.
