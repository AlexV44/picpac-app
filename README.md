# PicPac AI Prototype

ИИ-надстройка для редактора фотокниг Premium: пользователь загружает свои фото,
ИИ оценивает качество, кадрирует, улучшает и сам расставляет кадры по шаблону разворотов.

## Запуск

```
pip install -r requirements.txt
streamlit run app.py
```

При первом запуске приложение само скачает маленькую модель лиц YuNet (около 230 КБ)
в папку `models/`. Если интернета нет, будет использован Haar-каскад или YOLOv8
(если установлен `ultralytics`), а без них кроп опирается на карту заметности.

Ручная загрузка модели: https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet
(файл `face_detection_yunet_2023mar.onnx` положить в `models/`).

## Мобильное приложение (PWA, трек 2 хакатона)

```
pip install -r requirements.txt
python server.py          # http://localhost:8000/ (на ноутбуке откроется в рамке телефона)
python selftest.py        # 92 автоматических проверки за ~1 минуту, без ключей и браузера
python seed_data.py       # (по желанию) синтетические данные: 600 заказов, 240 клиентов, 320 обращений в seed/
```

**Тестовые учётные записи** (данные синтетические, пароли публичные): гость без пароля; клиент `client@picpac.test` / `client123`;
администратор `admin@picpac.test` / `admin123`. Две роли с разными правами, проверка на сервере.

**Документы для сдачи:** `docs/DEMO.md` (сценарий на 5–7 минут), `docs/ARCHITECTURE.md` (схема, потоки, формула цены), `docs/API.md`,
`docs/TEST_REPORT.md` (приёмка по критериям ТЗ), `LICENSES.md`.

**Переменные окружения:** `OPENROUTER_API_KEY` (необязательно), `PICPAC_DATA` (папка данных), `TRACK_STEP_SECONDS` (скорость статусов в демо, 25),
`PICPAC_DEMO=0` (запретить клиентам перематывать статусы), `PORT`. Секреты в репозитории не хранятся.

**Данные и приватность.** Проекты, фото, заказы и обращения лежат на сервере в `data/` до удаления (⚙ → «Удалить мои данные», удаление отдельных фото в их карточке).
Журнал `data/audit.log` не содержит телефонов и ключей. Внешний AI-API (OpenRouter, по ключу): в текстовую модель уходит только структура альбома и оценки качества,
в модель правки изображений только то фото, которое правит пользователь, и его запрос; регион обработки задаёт провайдер модели. Без ключа всё работает локально и офлайн.

**Известные ограничения.** Проекты (черновики) общие для сервера, заказы и обращения разделены по пользователям; оплата, push и доставка имитируются;
цены выше «от» демонстрационные; ИИ-апскейл и живой OpenRouter не проверялись в тестовой среде.

**Вкладки:** Главная · Фото · Альбом · Корзина · Заказы.

- **Главная** (шапка просто «Главная»): карточки услуг как на picpac.by (Фотопечать от 0,65, Фотокниги Classic от 72,90,
  Premium от 70,35, Цифровая печать от 0,49, Lite от 56,00; иллюстрации нарисованы кодом), «Продолжить» с черновиками и
  краткие карточки активных заказов. Нажатие на услугу открывает выбор параметров (обложка / формат и бумага) и ведёт на вкладку «Фото».
- **Фото → Альбом → Заказ** (шапка из трёх шагов). Стрелки «отменить/повторить» только на вкладке «Альбом». Название и тему
  меняют по нажатию на обложку. Для фотопечати вместо альбома список фото с количеством отпечатков.
- **Корзина:** можно собрать несколько альбомов и фотопечать за один заказ, у книг своё количество экземпляров.
  Каждый проект (фото, раскладка, тема, чат) сохраняется на диск (`data/projects/`) и переживает перезапуск.
- **Заказы:** активные и завершённые заказы этого устройства; нажатие открывает трекинг, ввод трек-кода не нужен
  (поиск по коду остаётся для заказов с другого устройства). Страница `/track/КОД` тоже работает.
- **Администратор** (`admin@picpac.test`): вместо клиентских вкладок главный экран — панель с вкладками «Сводка» (KPI, этапы), «Заказы» (поиск, фильтр, смена статуса), «Обращения», «Журнал».
- **Робот-помощник** (плавающая кнопка, ✕ закрывает панель). Запрос выполняется в фоне, экран не блокируется,
  в чат выводится сворачиваемый блок «Ход мыслей» (шаги и рассуждения модели, если она их отдаёт), затем отдельным сообщением итоговый ответ. Выбранное фото остаётся закреплённым, пока вы его не уберёте. Из фото и слота: «🤖 Спросить у ИИ про это фото».

**Что добавлено под ТЗ (трек 2):** вход (гость / аккаунт) и роли, каталог через API со сроками и требованиями к фото, проверка JPEG/PNG и лимитов, порядок фото,
автосохранение, проверка перед заказом (предупреждение «заменить или продолжить»), промокод и пересчёт цены, идемпотентный заказ, статусы в 5 группах,
push-имитация, история заказов, чат поддержки (⚙) с привязкой к заказу и ответами оператора, удаление данных, журнал операций, оффлайн-режим, доступность (фокус, Esc, контраст, aria).

**Сценарий (повторяется без помощи автора).** Главная → «Попробовать на демо-фото» (или выбрать услугу) → ИИ оценивает и собирает альбом →
правки (кадр, шаблон, тема, чат, «Спросить у ИИ») → «Заказ» (в корзину) → проверка перед печатью, получение, контакты →
заказ и **трек-код `PP-XXXX-XXXX`** → лента из 9 статусов (принят, оплата, ИИ-проверка, печать, переплёт, контроль, передан,
в пути, готов). В демо статусы идут сами раз в 25 с (`TRACK_STEP_SECONDS`), кнопка «Демо: следующий статус» перематывает сразу.

**Редактирование фото по тексту («✨ Магия»).** Из карточки фото, слота или чата («открой глаза на фото 2»,
«убери лишнее с фото 3», «сделай фото 1 в стиле Хэллоуин», «добавь шляпу»).
- Правки по просьбе: только локальные приёмы без генерации изображений нейросетью (стили Хэллоуин/Новый год/День рождения, ч/б, винтаж, мультяшный, ярче, удаление объекта по отметке). Генеративные модели (FLUX и др.) удалены.
- Без ключа работают локальные приёмы: Хэллоуин, Новый год, День рождения, ч/б, винтаж, мультяшный, «ярче»
  и удаление объекта по отметке (OpenCV inpaint). Остальные правки приложение честно отклоняет понятным сообщением.
- Результат сначала показывается «Было / Стало», потом «Заменить» или «Как новое»; оригинал можно вернуть.
- Ответ модели ~1 Мпикс: для печати это меньше оригинала, оценка качества это учитывает.

Кот и робот нарисованы кодом (`web/mascots.js`).

**Ноутбук и телефон.** На широком экране приложение показывается в рамке телефона (`?frame=0` отключает).
С телефона: `http://<IP-ноутбука>:8000/` в одной Wi-Fi сети. Установка на экран «Домой» требует HTTPS:
`ngrok http 8000`, `cloudflared tunnel --url http://localhost:8000` или `lt --port 8000`.

**Что в демо упрощено:** оплата без списания денег, цены примерные (`orders.py`, словарь `CATALOG`),
заказы лежат в `data/orders.json` (макеты в `data/orders/`), статусы моделируются
по времени, а не приходят из реальной печати. Ключ OpenRouter и модели задаются только на сервере: переменные `OPENROUTER_API_KEY` (можно положить в файл `.env` рядом с `server.py`, строка `OPENROUTER_API_KEY=sk-or-...`; сервер читает его при старте, после правки перезапустите сервер), `PICPAC_MODELS` (OpenRouter получает только текст чата, без фото) (или `POST /api/settings` от имени администратора). В интерфейсе приложения технических данных (модель, ключ, стоимость, названия библиотек) нет.

**Быстрые команды.** Действия альбома (заполнить слоты, переобрезать, поровну, пересобрать, добавить разворот, название и тема) собраны в панели «Быстрые команды» на вкладке «Альбом». Фото, прикреплённое в чате с ИИ, уходит с одним сообщением и после отправки открепляется.

Файлы: `server.py` (API), `imgedit.py` (правка фото), `orders.py` (заказы и статусы), `selftest.py`, `web/`.

## Структура

- `server.py`, `imgedit.py`, `orders.py`, `web/` — мобильная PWA (см. выше)
- `app.py` — интерфейс Streamlit в стиле PicPac (вкладки «Фото», «Развороты», «Редактор кадра», «Дизайн»)
- `assistant.py` — чат-ассистент: OpenRouter, строгие JSON-действия, проверка, выполнение, офлайн-разбор
- `themes.py` — темы оформления (день рождения, свадьба, путешествие, Новый год, минимализм, классика)
- `ai_core.py` — вся логика: качество, дубли, умный кроп, улучшение, шаблоны, раскладка, рендер, PDF

## Что делает ИИ

| Шаг | Как |
|---|---|
| Оценка качества | резкость (по лицу или по самому резкому участку), экспозиция, контраст, разрешение, эффективный dpi в конкретном слоте |
| Дубли | перцептивный хэш, остаётся лучший кадр |
| Умный кроп | перебор окон под форму слота: лица не режутся, воздух над головой, лица и линия глаз на третях, карта заметности |
| Улучшение | автоуровни, яркость, локальный контраст, шумоподавление, адаптивная резкость |
| ИИ-апскейл | Real-ESRGAN (realesr-general-x4v3, ~5 МБ), включается в «Дизайне» и работает только для слотов, где не хватает пикселей; лупа до/после в «Редакторе кадра» |
| Раскладка | выбор шаблона под ориентацию и качество кадров, венгерский алгоритм для слотов, хронологический порядок |

Улучшение умеренное: оно не восстанавливает сильно смазанные кадры и не добавляет
реальных пикселей. Для таких кадров приложение показывает предупреждение.

## Настройка порогов

В `ai_core.py`: `SHARP_LO` / `SHARP_HI` (резкость), `MIN_OK_DPI` и `TARGET_DPI` (печать),
`SPREAD_CM` (размер разворота, сейчас 28x20 см), словарь `TEMPLATES` (добавление шаблонов).

## ИИ-апскейл (Real-ESRGAN)

Нужен PyTorch: `pip install torch` (на CPU работает, но медленно: плитками по 256 px;
на видеокарте NVIDIA заметно быстрее). Веса (около 5 МБ) скачиваются при первом
включении в `models/realesr-general-x4v3.pth`. Если интернета нет, скачайте файл вручную:
https://github.com/xinntao/Real-ESRGAN/releases/download/v0.2.5.0/realesr-general-x4v3.pth

Апскейл применяется к кропу слота (не к целому фото) и только если пикселей не хватает
для выбранного dpi. Кадры крупнее ~1.5 Мпикс пропускаются (там он не нужен).
Если torch или веса недоступны, приложение работает как раньше и показывает причину.
Апскейл достраивает правдоподобные детали, а не восстанавливает реальные.

## Интеграция с CRM (персональные предложения)

Приложение запрашивает у CRM портрет вошедшего клиента и показывает на главной блок «Для вас» (день рождения, «мы скучаем», личная скидка,
бесплатная доставка для VIP, кросс-продажи), а при оформлении автоматически применяет скидку. Проценты считает сервер, клиент подменить их не может.
CRM недоступна: приложение работает как раньше. Демо-режим включён по умолчанию (`client@`, `vip@`, `sleep@picpac.test`), настоящая CRM
подключается переменными `CRM_MODE=http`, `CRM_URL`, `CRM_TOKEN`. Контракт API, правила и приватность: `docs/CRM.md`.

## Чат-ассистент (OpenRouter)

Вкладка «Ассистент»: пользователь пишет фразу («оформи как день рождения», «на втором развороте
сделай новогодний стиль», «перемешай фото», «назови книгу «Лето»»), модель превращает её в список
строгих действий (JSON), приложение проверяет их и выполняет. Модель не рисует и не исполняет код.

Ключ: переменная окружения `OPENROUTER_API_KEY`, файл `.streamlit/secrets.toml`
(`OPENROUTER_API_KEY = "sk-or-..."`) или поле во вкладке.

Модели по умолчанию (меняются в интерфейсе или в `assistant.DEFAULT_MODELS`):
основная `z-ai/glm-5.3-flash`, запасная `openai/gpt-oss-20b`. Обе дешёвые, с поддержкой JSON.
Кнопка «Проверить модели» сверяет их с каталогом OpenRouter и показывает цены. Если указанной
модели нет в каталоге, берётся первая существующая из запасного списка.
Стоимость одной команды порядка сотых долей цента (в чате показывается фактическая).

Приватность: в модель уходит только структура книги (шаблоны, номера слотов и фото, оценки
качества, даты). Фото и имена файлов не отправляются.

Если ключа нет, сеть недоступна или модель ответила мусором, работает офлайн-разбор по ключевым
словам (темы, перемешивание, порядок по дате, раскладка, названия, добавить и удалить разворот).

Действия: apply_theme, set_text, change_template, swap_photos, set_photo, remove_photo,
rearrange (shuffle, chronological, best_first, relayout, replan), recrop, add_spread,
remove_spread, fill_empty. Новые темы добавляются в словарь `THEMES` в `themes.py`.


## База данных и аккаунты (кратко)
- PostgreSQL: `createdb picpac` (или пропустите, `db.py` создаст сам), затем `export DATABASE_URL=postgresql://user:pass@localhost:5432/picpac` и `python db.py init` (создаёт базу, если её нет, и применяет `db/schema.sql`; можно и `psql -d picpac -f db/schema.sql`). Без `DATABASE_URL` используется SQLite. Подробности: docs/DB.md.
- Регистрация и вход: экран входа, вкладка «Регистрация». У каждого пользователя своя сессия и свои проекты; гостевой режим остаётся.
- Автоулучшение фото выключено по умолчанию: включается переключателем в «Быстрых командах» для всего проекта или кнопкой «Улучшить» для одного фото.
- Проверка: `python selftest.py` (124 проверки).

## Оформление и ресурсы (раунд I)
- Иллюстрации главной и входа нарисованы кодом: `python tools/make_art.py` (нужны rsvg-convert и Pillow); файлы `web/img/hero.jpg`, `web/img/login.jpg` можно заменить своими.

- Фото группируются по дате съёмки (из файла, иначе по дате файла на телефоне). Ничего не раскладывается по альбому само: только «Быстрые команды» или кнопка «Разложить по альбому».
- Стили оформления: 17 тем (добавлены Полночь, Изумруд, Нежность, Скандинавия, Винтаж, Лето, Закат, Океан, Лён, Малыш).

## Создание альбома, проекты, просмотр (раунд J)
- Нижняя панель: Главная, Фото, Проекты, Корзина. Черновики и незаконченные проекты живут во вкладке «Проекты».
- Два способа создать фотокнигу: «По шаблону» (10 готовых: День рождения, Свадьба, Новый год, Путешествие, Хэллоуин, Первый год малыша, История любви, Лето у моря, Семейный архив, Выпускной) и «Вручную» (чистый альбом: тема и цвет фона каждого разворота, цвет обложки, раскладка, тексты). ## Раунд K (фотобаллы, совместный альбом, белорусский, правки)

- **Название**: приложение называется PicPac (без «AI»).
- **Фотобаллы** (`loyalty.py`, `GET /api/loyalty`): 1 балл = 1 руб. Начисление по сумме заказа (шкала под печать: 10–30 руб. → 1, 30–60 → 3, 60–100 → 6, 100–200 → 12, 200–400 → 28, от 400 → 70), ×2 в праздники и в день рождения из CRM, +5 приветственных, баллы приходят после выдачи заказа. Списание: после покупок на 30 руб., до 10/15/20% стоимости заказа, не суммируется с промокодом и персональной скидкой. Баланс считается из заказов (нельзя накрутить). На главной: карточка баллов, «?» и окно «Как это работает» с таблицами. Только для вошедшего клиента (не гость, не админ). В оформлении заказа переключатель «Оплатить фотобаллами».
- **Совместный альбом** (`POST /api/share`, `/join/<token>`): владелец включает ссылку («Поделиться» на вкладке «Альбом»). Участник (в том числе гость) добавляет фото в общий пул (до 40 на человека), видит пул, удаляет только свои; макет и заказы владельца недоступны. Фото участников помечены «от Имени». Выключение или «новая ссылка» отзывает доступ.
- **Белорусский язык**: `web/i18n.js`, переключатель RU/БЕЛ на входе и в профиле; ответы робота тоже на выбранном языке. Админ-панель остаётся на русском.
- **Автокадрирование по желанию**: по умолчанию кадр по центру; умное кадрирование по лицам только по кнопке (на фото, в слоте или «Быстрые команды»).
- **Исправлена ошибка чата**: после смены раскладки следующие действия проверяются по новой раскладке; смена шаблона добирает свободные фото.
- Убран часовой пояс «(+0300)», компактные кнопки «Просмотр / Быстрые команды / Поделиться». selftest: 156 проверок.

## Раунд L

## Раунд M: каталог и цены через API
- Каталог больше не зашит в `orders.py`. Источник: `CATALOG_API_URL` (внешний или mock API) → `data/catalog.json` → `seed/catalog.json` (модуль `catalog_api.py`).
- Встроенный mock API: `/mock-api/v1/catalog`, `/products`, `/delivery`, `/promos`, `/prices`; `PUT /mock-api/v1/catalog` (админ) меняет цены без перезапуска.
- Сервер кэширует каталог на `CATALOG_TTL` секунд (30) и при падении внешнего API держит последнюю рабочую версию.
- Интерфейс получает каталог только через `GET /api/catalog` (ETag, перезагрузка при смене `version`), последняя копия лежит в localStorage на случай отсутствия сети.
- Чтобы проверить «внешний» режим: `$env:CATALOG_API_URL="http://127.0.0.1:8000/mock-api/v1/catalog"` (PowerShell).

## Раунд M, часть 2
- **Вкладка «Цены» в админке:** товары, форматы, обложки, доставка, промокоды; «Сохранить цены» и «Вернуть исходный каталог». Каждое изменение пишется в журнал с деталями («Фотокниги Premium: цена 70.35 → 75.5»).
- **Фото в БД:** у вошедших пользователей в таблице `photo_blobs`; у гостей во временном кэше (24 часа), при входе переносятся в БД. Старые файлы переносятся при запуске.
- **Офлайн-очередь загрузки:** выбранные фото сохраняются на устройстве (IndexedDB) и догружаются сами при появлении сети или при следующем запуске; повторная отправка заказа не создаёт дубль (ключ идемпотентности).
- **Deep links:** `/p/<проект>`, `/catalog`, `/catalog/<услуга>`, `/orders`, `/cart`; без входа ссылка запоминается и открывается после входа.
- **Аналитика воронки** в сводке админки: каталог → проект → фото → корзина → оформление → заказ (уникальные пользователи, конверсия шага).
- Кнопки «Удалить мои данные» (профиль) и «Удалить фото» (карточка фото) уже были.

## Раунд M, часть 3: гибкая админка
Вкладка «Каталог» (бывшая «Цены») позволяет добавлять и удалять товары (фотокниги и печать), форматы, бумагу, обложки, способы доставки и оплаты, промокоды, редактировать названия, описания, сроки, цены, а также отключать пункты галочкой. Правки применяются после «Сохранить», пишутся в журнал (что добавлено, удалено, изменено), можно «Отменить правки» или «Вернуть исходный каталог». Зашитых в код id больше нет: умолчания берутся из первых включённых пунктов каталога.

## Раунд M, часть 4: удалённое из каталога
Если админ убрал то, что пользователь уже выбрал, проект не ломается: пользователь видит мягкое окно («Этой услуги больше нет… выберите, на что заменить») с вариантами замены, метку «нужна замена» в проектах и корзине, а заказ не оформляется, пока позиция не заменена. Фото и макет сохраняются. Названия выбранных пунктов запоминаются в проекте, а старые заказы хранят название и тип товара сами.
